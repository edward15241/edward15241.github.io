# 週報自動發布到網站

給定期產出「語音技術週報」的 Claude routine 用的作業說明。
產出格式不必改，只要把最後的輸出從 artifact 換成推進這個 repo。

---

## ⚠️ 先確認：這個網站是公開的

`edward15241/edward15241.github.io` 是 **public repo**，
發布後的網站 <https://edward15241.github.io> 任何人都能瀏覽，
搜尋引擎也會收錄。

**可以放：** 公開論文、arXiv 預印本、開源模型發布、產業新聞、官方公告，
以及對這些公開資訊的技術整理與摘要。

**不可以放：**

- 任職公司的內部評論、策略判斷、產品規劃
- 未公開的研究方向、實驗數據、內部評測結果
- 客戶名稱、專案代號、任何簽了保密義務的內容
- 他人的個資

判準不是「有沒有人會看」，而是**「這段文字被不認識的人看到會不會有問題」**。
只要有一項不確定，就不要推上去——先問過再說。

**另外注意：git 歷史是永久的。**
公開 repo 一旦推上去，之後就算刪檔案，任何人都能從舊 commit 翻出來。
「先放上去、之後再刪」在這裡行不通。

## 作業步驟

### 1. 把週報存成檔案

現在的 HTML 格式不用改，`<style>` 區塊帶著也沒關係，轉換工具會處理。
檔名建議帶上日期範圍，例如：

```
語音技術週報_2026-08-17_to_2026-08-24.html
```

### 2. 取得 repo

```bash
git clone https://github.com/edward15241/edward15241.github.io.git
cd edward15241.github.io
```

（已經有的話跑 `git pull` 就好。）

### 3. 轉換並更新列表

```bash
python3 tools/import_weekly.py /path/to/語音技術週報_2026-08-17_to_2026-08-24.html
python3 tools/build_index.py
```

`import_weekly.py` 會自動處理：

- 從 `<title>` 或內文取出標題與日期範圍，決定輸出檔名
  （`notes/YYYY-MM-DD-標題.html`，日期用該期的結束日）
- 判斷來源格式：**純標籤版**（只有 `<h1>`/`<h2>`/`<ul>`）
  或**卡片版**（自帶 `<style>`，含 `.summary-box`／`.topic`／`.item`／`.ds-table`）
- 套上站內版型：接上 `assets/css/style.css`、加頁首頁尾與返回連結
- 卡片版的類別會改名成站內的 `.wr-*` 系列，樣式由 style.css 提供，
  頁面本身不需要內嵌 CSS
- 移除開頭的 `Artifact 來源:` 那行（該連結外部讀者打不開）

`build_index.py` 掃描 `notes/` 重建首頁列表，日期新的排前面。
**首頁列表不要手動編輯**，會被這支程式蓋掉。

### 4. 確認產出

推之前先看一眼轉出來的檔案，確認標題、日期、連結都正常。
有 Python 的話可以本機起個伺服器看：

```bash
python3 -m http.server 8000
# 開 http://localhost:8000
```

### 5. 推送

```bash
git add -A
git commit -m "新增週報 2026-08-17 – 08-24"
git push origin main
```

推到 `main` 後，GitHub Pages 會自動建置，約 30 秒到 1 分鐘後上線。

## 疑難排解

**轉換時說「找不到日期範圍」**
　來源檔的標題或檔名要含得出日期，支援這兩種寫法：
　`2026 / 08 / 17 – 08 / 24`（標題內）或 `2026-08-17_to_2026-08-24`（檔名）。
　都沒有的話，手動把檔名改成後者再跑一次。

**推上去了但網站沒更新**
　先確認推的是 `main` 分支。再到 repo 的 Actions 分頁看
　`pages build and deployment` 這個工作流程有沒有跑、有沒有失敗。
　瀏覽器可能有快取，用 Ctrl+Shift+R 強制重新整理。

**同一期重複發布**
　輸出檔名由日期與標題決定，同一期會覆蓋原檔，不會產生重複條目。
　真的要移除某期，刪掉 `notes/` 底下的檔案再跑一次 `build_index.py`。
