# SOT-family methods for overlapped speech and their applicability to Qwen3-ASR-0.6B

> Research date: 2026-11-10. Evidence grades used below:
> **[CODE]** = read directly from a cloned GitHub repo / the tech-report PDF shipped in the official repo (highest confidence).
> **[PAPER]** = read directly from the arXiv HTML/PDF full text or from the Hugging Face checkpoint files (config.json / tokenizer_config.json / chat_template.json), fetched late in the session after the network allowlist was widened. Numbers are copied from the paper's tables.
> **[SEARCH]** = taken from a web-search summary/snippet of the primary paper only (the full text was not read). Numbers with this grade should be re-checked against the PDF before being quoted in a final report.
> "Not Reported" = looked for and not found in the source that was accessible.

## 1. Exact definitions, target formats and losses of SOT, t-SOT, SOP (and other serialization variants); pros/cons; which need architecture changes

### Takeaway
SOT (utterance-level) and t-SOT (token-level) are pure *label-format* changes trained with the ordinary cross-entropy of a single-output decoder, so they need no architecture change beyond one delimiter token; SOP (Shi et al., ASRU 2025) and its relatives (EncSep/GEncSep, BA-SOT, SA-SOT, learned-dominance SOT, DiCoW-SOT) all add modules (separator, per-speaker CTC heads, extra losses, diarization conditioning) and are therefore *not* "target-only" changes. For an offline, no-diarization "recover all text" goal, plain utterance-level SOT is the variant that maps onto an Audio-encoder + projector + LLM model without touching the model.

### Cited Findings

**SOT (Kanda et al., Interspeech 2020, arXiv 2003.12687)**
- [SEARCH] SOT uses "a model with only one output layer that generates the transcriptions of multiple speakers one after another", replacing the multiple output branches of PIT; it "introduces a special symbol to represent the speaker change" and concatenates the reference labels by inserting that symbol between utterances. — [arXiv 2003.12687](https://arxiv.org/abs/2003.12687), [ISCA PDF](https://www.isca-archive.org/interspeech_2020/kanda20b_interspeech.pdf)
- [SEARCH] Loss: ordinary attention-encoder-decoder cross-entropy on the serialized sequence (no PIT loss). Two orderings were considered: minimum-loss over all speaker permutations (O(S!) cost) and "first-in, first-out" (sort by each utterance's start time; only requirement is that utterances do not start at exactly the same time). — [arXiv 2003.12687](https://arxiv.org/pdf/2003.12687)
- [SEARCH] Because the number of `<sc>` symbols is free, the model is not tied to a fixed maximum speaker count and implicitly counts speakers; the abstract states SOT models "can transcribe overlapped speech with variable numbers of speakers significantly better than PIT-based models". — [arXiv 2003.12687](https://arxiv.org/abs/2003.12687)
- [CODE] The LibriSpeechMix evaluation set built for SOT consists of *partially* overlapped mixtures (not fully overlapped), has 1-, 2- and 3-speaker sets in which each LibriSpeech utterance is used exactly N times in the N-speaker set, and stores a per-utterance `delays` field (seconds; e.g. `[0.0, 4.469...]`) and a `texts` list per mixture. — [NaoyukiKanda/LibriSpeechMix README](https://github.com/NaoyukiKanda/LibriSpeechMix)

- [PAPER] Verified in full text: "the AED is trained to recognize the utterances of multiple speakers in the order of their start times, separated by a special symbol ⟨sc⟩ ... The only assumption to perform this first-in, first-out training is that the two utterances do not start at exactly the same time. If that is the case, we randomly determine the utterance order." The number of speakers is obtained "just by counting the occurrences of" ⟨sc⟩. — [arXiv 2003.12687 §4.1/4.3](https://arxiv.org/html/2003.12687)
- [PAPER] SOT needs capacity: "We found that the large model size was essential for SOT to achieve good results. This is because the attention and decoder modules in the SOT framework are required to work on contaminated embeddings" (512-dim 44.7M params: 5.4 / 17.3 / 34.3 WER on 1-/2-/3-speaker test; 1024-dim 143.9M: 4.8 / 10.9 / 25.8; 1024-dim + "separation after attention": 4.6 / 11.2 / 24.0). — [arXiv 2003.12687 Table 3](https://arxiv.org/html/2003.12687)
- [PAPER] SOT vs PIT (1024-dim): 2-output PIT trained on 1,2 speakers = 6.7 / 11.9 / (52.3); SOT trained on 1,2,3 speakers = 4.6 / 11.2 / 24.0 (1-/2-/3-speaker test); "PIT showed severe WER degradation for the 1-speaker case"; 3-output PIT "required impractical training time". — [arXiv 2003.12687 Table 4](https://arxiv.org/html/2003.12687)

**t-SOT (Kanda et al., Interspeech 2022, arXiv 2202.00842)**
- [PAPER] t-SOT labels were built with word time-alignments from the Montreal Forced Aligner ("If one word consisted of multiple subwords, the emission time was shared for all subwords"); the model assumes "up to two concurrent utterances" in the basic form and keeps "the same architecture as the single-talker ASR model ... without any modification". — [arXiv 2202.00842](https://arxiv.org/html/2202.00842)
- [SEARCH] "The t-SOT model has only a single output branch that generates recognition tokens (e.g., words, subwords) of multiple speakers in chronological order based on their emission times. A special token ⟨cc⟩, which indicates a change of 'virtual' output channels, is inserted between two adjacent words if they are spoken by two different speakers." — [arXiv 2202.00842](https://arxiv.org/abs/2202.00842), [ISCA PDF](https://www.isca-archive.org/interspeech_2022/kanda22_interspeech.pdf)
- [SEARCH] For >2 simultaneous speakers, channel-specific tokens ⟨cc_m⟩ are used so that the same virtual channel is not used by multiple speakers at the same time; at inference the stream is "deserialized" into M virtual channels, the first token always going to channel 1. — [arXiv 2202.00842](https://arxiv.org/pdf/2202.00842)
- [SEARCH] The paper's appendix states a t-SOT model can be used as a single-talker model by setting the output probability of ⟨cc⟩ to zero. — [arXiv 2202.00842](https://arxiv.org/pdf/2202.00842)
- [SEARCH] t-SOT requires word/token-level timestamps for building training targets (tokens are sorted by emission time); it was designed for *streaming* (transducer) models. — [arXiv 2202.00842](https://arxiv.org/abs/2202.00842)
- [SEARCH] Known weakness of t-SOT, per the SA-SOT paper: frequent speaker changes interleave words of different speakers and cause "semantic confusion", making it harder for the decoder to use context. — [SA-SOT, arXiv 2403.02010](https://arxiv.org/pdf/2403.02010)

**SOP — Serialized Output Prompting (Hao Shi, Fujita, Mizumoto, Liu, Kojima, Sudo; SB Intuitions; ASRU 2025; arXiv 2509.04488)**
- [SEARCH] Motivation: "existing LLM-based multi-talker ASR systems either omit prompts or rely on simple task-definition prompts"; SOP extracts multi-talker content from the speech and feeds it to the LLM as a structured prompt. — [arXiv 2509.04488](https://arxiv.org/abs/2509.04488)
- [SEARCH] Method: "A Separator and serialized Connectionist Temporal Classification (CTC) layers are inserted after the speech encoder to separate and extract MT content from the mixed speech encoding in a first-speaking-first-out manner." "The greedy search results of the serialized CTC are referred to as serialized output prompting (SOP), which are used as prompts for LLM decoding." — [arXiv 2509.04488](https://arxiv.org/html/2509.04488)
- [SEARCH] Training is three-stage: (1) SOT fine-tuning, (2) serialized speech information extraction (separator + serialized CTC), (3) SOP-based adaptation. — [arXiv 2509.04488](https://arxiv.org/abs/2509.04488)
- [SEARCH] Stated finding: the plain SOT-based LLM "performs well in the two-talker scenario" but "fails to fully leverage LLMs under more complex conditions, such as the three-talker scenario"; SOP improves both 2- and 3-talker LibriMix conditions. — [arXiv 2509.04488](https://arxiv.org/abs/2509.04488)
- [PAPER] Setup: speech encoder WavLM-Large ("as WavLM includes MT data in its pre-training"), CNN down-sampling + projector, LLaMA-3.2-1B / 3.2-3B / 3.1-8B with LoRA; LibriMix with ESPnet SOT offset files (Libri2Mix train ≈270 h, Libri3Mix ≈186 h), no extra augmentation. Stage 1 (= the SOT baseline) trains the *speech encoder* and the LoRA-adapted LLM with CE, then merges LoRA; Stage 2 trains speech encoder + down-sampling CNN + Separator + serialized CTC layers (CE + CTC); Stage 3 adds a new LoRA set, "Only the LoRA parameters are trainable", encoder/separator/CTC frozen. LLM input = [E_sop; H_p; E_t] (SOP token embeddings + mixed-speech embedding + text prompt). "We attempted to train all parameters directly in a single stage, but the system performance was suboptimal." — [arXiv 2509.04488 §III–IV](https://arxiv.org/html/2509.04488)
- [PAPER] Table I (WER %, Dev/Eval). Columns: Noisy Libri2Mix | Noisy Libri3Mix | Clean Libri2Mix | Clean Libri3Mix.
  - LLaMA-1B: SOT baseline (stage 1) 12.4/11.3 | 39.8/39.1 | 4.6/4.6 | 21.5/21.6; SOT-CTC (stage 2) 14.8/13.4 | 39.1/38.0 | 5.5/5.5 | 23.9/24.6; SOP (stage 3) 11.8/10.5 | 29.6/28.5 | 3.9/4.0 | 20.8/22.0; single-stage training 13.1/11.8 | 35.0/33.9 | 4.1/4.0 | 22.2/23.7; SOP prompt *without* mixed speech encoding 33.1/34.4 | 76.6/83.2 | 16.3/19.0 | 74.9/76.5.
  - LLaMA-3B: SOT baseline 11.2/9.8 | 34.2/31.7 | 4.0/4.1 | 22.3/22.0; SOP 10.5/9.2 | 29.3/28.1 | 3.5/3.6 | 17.0/16.5.
  - LLaMA-8B: SOT baseline 16.1/14.3 | 48.7/47.5 | 6.6/6.5 | 32.5/32.0; SOP 15.0/12.7 | 40.0/38.1 | 5.3/5.5 | 24.4/23.4. "Although the 8B model has more parameters, it did not lead to further improvement. We hypothesize that this is due to the limited amount of data." — [arXiv 2509.04488 Table I](https://arxiv.org/html/2509.04488)
- [PAPER] Table II context: non-LLM GEncSep = 15.0 (noisy Libri2Mix eval), 25.9 (noisy Libri3Mix eval), 6.6 / 13.1 (clean 2mix / 3mix eval). So plain SOT-LLM already beats non-LLM systems on 2-talker (e.g. 4.1 vs 6.6 clean) but is *worse* than them on 3-talker (22.0 vs 13.1 clean). Authors' explanation: "LLM-based SOT-ASR systems rely solely on self-attention. Due to the presence of down-sampling layers and the projector layer, the speech embeddings are mapped into the representation space of text embeddings, resulting in the loss of some speech-specific information." — [arXiv 2509.04488 Table II, §IV-D](https://arxiv.org/html/2509.04488)
- [CODE] Official code release (covers both SOP and the SLT 2024 EncSep paper): WavLM front-end; optional LSTM separator splitting encoder features into N per-speaker streams supervised by per-speaker CTC heads; LLaMA decoder (LLaMA-3.2 1B/3B, LLaMA-3.1 8B, base or Instruct) generating all N transcriptions as one serialized sequence separated by a `<sc>` token. Loss modes: `attention` (CE only = "pure SOT baseline"), `ctc`, `hybrid` = α·CE + (1−α)·CTC with `ctc_alpha` default 0.7. — [hshi-speech/Multi-talker-ASR-with-LLMs README](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs)
- [CODE] The same repo *adds* special tokens (`<bos_prompt>`, `<eos_prompt>`, `<bos_speech>`, `<eos_speech>`, `<bos_response>`, `<eos_response>`, `<sc>`) when combining `microsoft/wavlm-large` with LLaMA; example recipe freezes encoder and decoder, unfreezes `enc_to_dec_proj`, and uses LoRA on decoder self-attention `k/q/v/o_proj` with r=16, alpha=32, dropout 0.1. Targets only LibriMix 2mix/3mix. — [hshi-speech/Multi-talker-ASR-with-LLMs README](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs)
- [SEARCH] Follow-ups by the same first author: "Beyond Acoustic Prefixes: Persistent Access to Serialized Acoustic Memory for LLM-based Multi-Talker ASR" (arXiv 2603.27205; listed in IEEE TASLP 2026) reports consistent improvements over static-prefix prompting on LibriMix; "Distilling LLM Semantic Priors into Encoder-Only Multi-Talker ASR with Talker-Count Routing" (arXiv 2603.10587) uses the LLM only as a training-time teacher and adds a Talker-Count Head that selects the decoding branch, arguing LLM decoders are slow and their gains "do not reliably transfer to challenging three-talker mixtures". — [IEEE SPS listing](https://signalprocessingsociety.org/publications-resources/ieee-transactions-audio-speech-and-language-processing/2026/10/beyond-acoustic-prefixes-persistent-access-serialized-acoustic-memory-llm-based-multi-talker), [arXiv 2603.10587](https://arxiv.org/abs/2603.10587)

**Other serialization variants**
- [SEARCH] Overlapped Encoding Separation — EncSep / GEncSep (Shi, Gao, Ni, Kawahara; SLT 2024; arXiv 2409.00815): adds a separator after the encoder, trained with CTC losses, so that CTC–attention hybrid training becomes possible for SOT; the separated per-speaker encodings are concatenated to guide attention decoding (GEncSep). Evaluated on Libri2Mix/Libri3Mix. Exact WERs: Not Reported (table headers unreadable in snippet). — [arXiv 2409.00815](https://arxiv.org/abs/2409.00815)
- [SEARCH] BA-SOT (Interspeech 2023, arXiv 2305.13716): adds a speaker-change-detection task + boundary constraint loss on the decoder and a two-stage CTC strategy; vs. original SOT it reduces CER by 5.1% and UD-CER by 14.0% relative (8.4% / 19.9% when initialised from a pre-trained ASR model). — [arXiv 2305.13716](https://arxiv.org/abs/2305.13716)
- [SEARCH] SA-SOT (arXiv 2403.02010): auxiliary loss on *masked t-SOT* labels plus a speaker-similarity matrix that reshapes decoder self-attention; relative cpWER reduction of 12.75%–22.03% on LibriSpeech multi-talker test sets. — [arXiv 2403.02010](https://arxiv.org/pdf/2403.02010)
- [SEARCH] SMA-SOT (Interspeech 2025): soft monotonic alignment loss + utterance-level timestamps; 5.4% relative CER reduction vs SOT, 0.35% vs BA-SOT. — [ISCA PDF](https://www.isca-archive.org/interspeech_2025/tan25_interspeech.pdf)
- [SEARCH] "Serialized Output Training by Learned Dominance" (arXiv 2407.03966): an auxiliary module in the AED learns the serialization order ("dominance score") instead of a fixed rule; reported to significantly outperform PIT and FIFO baselines on LibriSpeech/LibriMix 2-mix and 3-mix. — [arXiv 2407.03966](https://arxiv.org/abs/2407.03966)
- [SEARCH + CODE] SA-DiCoW / SOT-DiCoW (BUT, arXiv 2510.03723): DiCoW (diarization-conditioned Whisper) encoder produces per-target-speaker embeddings that are joined and decoded by a shared decoder with SOT; reported to beat DiCoW on LibriMix-type mixtures. The repo config uses `mt_sot_aggregation_type: "concat"`, `mt_num_speakers: 8`, `mt_sot_augment_speaker_order: true`; the dataset code supports two SOT styles ("utterance" = sort segments on start time, and "speaker") and raises "SOT needs timestamps to distinguish speakers!". Requires diarization input, so it is outside the "no diarization" scope. — [arXiv 2510.03723](https://arxiv.org/pdf/2510.03723), [BUTSpeechFIT/SOT-DiCoW](https://github.com/BUTSpeechFIT/SOT-DiCoW)

### Inferences
- (Inference) Comparison for this project's goal (offline, 2 talkers, text only):

| Method | Target format | Loss | Extra modules | Needs timestamps to build labels | Fit for Enc+Proj+LLM "target-only" |
|---|---|---|---|---|---|
| SOT | `spk1 text <sc> spk2 text`, FIFO by start time | CE | none (1 delimiter token) | utterance start times only | Yes |
| t-SOT | tokens interleaved by emission time with `<cc>` | CE (originally RNN-T) | none | word-level timestamps | Possible but poor fit: interleaving breaks LLM language-model context; benefit is streaming, which is not required |
| SOP | SOT target + CTC-derived text prompt | CE + per-speaker CTC, 3 stages | separator + serialized CTC heads | utterance start times | No (architecture + pipeline change) |
| EncSep/GEncSep, BA-SOT, SA-SOT, learned-dominance | SOT/t-SOT | CE + auxiliary | yes | varies | No |
| SOT-DiCoW | SOT | CE | diarization conditioning | diarization | No |

- (Inference) t-SOT's interleaved word stream conflicts with what an LLM decoder is good at (fluent continuation); all LLM-based MT-ASR papers found here (Shi et al. 2408.17431, MT-LLM, SOP) use *utterance-level* SOT, none t-SOT. This is consistent with — but not proof of — utterance-level SOT being the right default for Qwen3-ASR.
- (Inference) SOP's reported benefit is mostly in the 3-talker condition; for a strictly 2-talker requirement, the evidence that plain SOT already "performs well" suggests starting with plain SOT and keeping SOP-style CTC guidance as a later option.

### Gaps
- SOT (2003.12687), t-SOT (2202.00842), SOP (2509.04488), Shi et al. (2408.17431), MT-LLM (2409.08596) and Li et al. (2305.18747) were read in full text late in the session ([PAPER]). BA-SOT, SA-SOT, SMA-SOT, learned-dominance SOT, EncSep, SA-DiCoW, SpeakerLM, MOSS-Transcribe-Diarize remain [SEARCH]-grade only.
- "CTC-guided ordering" as a named method: Not found as a distinct paper; the nearest are serialized-CTC in "first-speaking-first-out" order (SOP/EncSep) and learned-dominance ordering (2407.03966).
- Speaker-aware CTC (arXiv 2409.12388) and Speaker-Distinguishable CTC (arXiv 2506.07515) surfaced in search but were not examined.

## 2. How do SOT papers order speakers' text in overlap, and what do ablations show?

### Takeaway
FIFO by utterance start time is the de-facto standard (original SOT, SOT-Whisper, SOT-DiCoW "utterance" style, SOP's "first-speaking-first-out" CTC); the original SOT paper found FIFO better than minimum-loss permutation ordering, and the known weak spot is mixtures whose utterances start at (nearly) the same time, which motivated learned-dominance ordering.

### Cited Findings
- [PAPER] Original SOT Table 1 (512-dim models, 2-speaker mixtures, WER % dev_clean / test_clean): single-speaker ASR 67.9 / 68.5; SOT (minimum loss speaker order) 17.4 / 17.1; SOT (first-in, first-out) 17.0 / 16.5. "Surprisingly, the 'first-in, first-out' training achieved a better WER than the 'minimum loss speaker order' training although the former approach can be executed with a computational cost of O(S)". FIFO was used for all remaining experiments. — [arXiv 2003.12687 Table 1, §5.2](https://arxiv.org/html/2003.12687)
- [PAPER] Training-data constraint used to make FIFO well defined: delays were random subject to "(1) the start times of the individual utterances differ by 0.5 s or longer and (2) every utterance in each mixed audio sample has at least one speaker-overlapped region". The evaluation set did *not* impose (1), so "all possible permutations of the hypothesis order were examined, and the one that yielded the lowest WER was picked". — [arXiv 2003.12687 §5.1](https://arxiv.org/html/2003.12687)
- [PAPER] Other orderings in the LLM papers are also FIFO: MT-LLM "transcribing the utterances of multiple talkers in the order of their start times, separated by '<sc>'"; Shi et al. use "speaker-wise FIFO" with "$" as the speaker-change symbol on AMI utterance groups; ESPnet's LibriMix SOT recipe adds "a random delay ranging from 1 to 1.5 seconds" to the otherwise fully-overlapped LibriMix. — [arXiv 2409.08596](https://arxiv.org/html/2409.08596), [arXiv 2408.17431](https://arxiv.org/html/2408.17431)
- [SEARCH] FIFO requires only that utterances do not start at exactly the same time; later work notes FIFO "fails in 0s-offset overlap" and that exhaustive min-loss ordering is infeasible beyond two speakers. — [arXiv 2003.12687](https://arxiv.org/pdf/2003.12687), [arXiv 2407.03966](https://arxiv.org/pdf/2407.03966)
- [SEARCH] Learned-dominance SOT replaces the rule with a learned ordering and reports significant gains over both PIT and FIFO on LibriSpeech/LibriMix 2-mix and 3-mix. Numbers: Not Reported. — [arXiv 2407.03966](https://arxiv.org/abs/2407.03966)
- [SEARCH] SMA-SOT argues the FIFO principle "complicates strict temporal monotonicity" of attention and adds a soft monotonic alignment loss. — [ISCA Interspeech 2025](https://www.isca-archive.org/interspeech_2025/tan25_interspeech.pdf)
- [CODE] SOT-Whisper (Chan & Lian 2026): reference text is `"<utt1> <|cc|> <utt2>"`; mixtures are made on the fly by `mix_audio_fixed_delay(sig1, sig2, delay)` (zero-pad sig2 by `delay` seconds, then `sig1 + sig2_delayed` — plain sum, no gain scaling in this function); the CSV has a per-row `delay` column, so the first-listed utterance is the earlier one (FIFO). Evaluation code contains `swap_before_after_special_token`, i.e. the hypothesis is also scored with the two halves swapped (order-tolerant scoring). — [Greg0124/SOT-Whisper-MultiSpeaker-ASR mix_process.py / train.py](https://github.com/Greg0124/SOT-Whisper-MultiSpeaker-ASR)
- [CODE] SOT-DiCoW: `segments.sort(key=lambda s: s.start)` for the "utterance" SOT style; the training config additionally enables `mt_sot_augment_speaker_order: true`. — [BUTSpeechFIT/SOT-DiCoW](https://github.com/BUTSpeechFIT/SOT-DiCoW)
- [SEARCH] SOP/EncSep extract per-speaker content with serialized CTC in "first-speaking-first-out" order. — [arXiv 2509.04488](https://arxiv.org/abs/2509.04488)

### Inferences
- (Inference) For synthetic 2-speaker training data, always impose a non-zero start offset between the two utterances (as LibriSpeechMix does via `delays`) so that the FIFO target is well defined; exactly simultaneous starts make the label order arbitrary and are a documented failure mode.
- (Inference) Evaluation should be permutation-invariant over the `<sc>`-separated segments (as in SOT-Whisper's swap scoring / cpWER-style), otherwise correct text in the "wrong" order is penalised twice.

### Gaps
- No ablation was found comparing FIFO against *loudness/energy-based* ordering ("dominant speaker first"); search explicitly returned none.
- No ordering ablation specific to LLM-decoder MT-ASR was found (all LLM papers found simply adopt FIFO SOT).

## 3. One model for both single- and multi-speaker audio; avoiding a hallucinated second speaker (speaker counting, mixing ratios)

### Takeaway
Every SOT system found trains on a mixture of single-talker and multi-talker samples with the *same* output format (single-talker targets simply contain no delimiter). With such mixing, SOT showed no single-talker degradation (5.7 → 5.4–5.7 WER) and 99.8% / 97.0% speaker-counting accuracy on 1-/2-speaker simulated audio; *without* single-talker data, single-talker WER collapsed to 16.7. On real meetings (AMI) counting is much weaker (≈77–81% for 2 talkers; 3–8% of 1-talker groups get a spurious second speaker). Exact single:multi sampling ratios are generally Not Reported.

### Cited Findings
- [PAPER] SOT Table 2 (512-dim, WER % on 1 / 2 / 3-speaker test; parentheses = unmatched condition): single-speaker ASR 5.7 / (68.5) / (92.7); SOT trained on 2-speaker only (16.7) / 16.5 / (55.2); SOT trained on 1,2 speakers 5.7 / 18.6 / (59.7); SOT trained on 1,2,3 speakers 5.4 / 17.3 / 34.3. "The SOT model did not show any degradation for the single-speaker case, sometimes even outperformed the single-speaker ASR model. This might be because of the data augmentation effect resulting from mixing training utterances." — [arXiv 2003.12687 Table 2](https://arxiv.org/html/2003.12687)
- [PAPER] How the mix was built: "For each training example, we firstly determined the number of speakers S ... For each utterance in train_960, (S−1) utterances were randomly picked up" — the distribution over S (single:multi ratio) is Not Reported. — [arXiv 2003.12687 §5.1](https://arxiv.org/html/2003.12687)
- [PAPER] SOT Table 5, speaker counting (1024-dim SOT, trained on 1,2,3 speakers; rows = actual, cols = estimated 1 / 2 / 3 / >4): actual 1 → 99.8 / 0.2 / 0.0 / 0.0; actual 2 → 1.9 / 97.0 / 1.1 / 0.0; actual 3 → 0.2 / 24.0 / 74.2 / 1.5. I.e. a spurious 2nd speaker in 0.2% of single-speaker samples; a missed 2nd speaker in 1.9% of 2-speaker samples. — [arXiv 2003.12687 Table 5](https://arxiv.org/html/2003.12687)
- [PAPER] Real-data counting is harder. Shi et al. Table 6 (AMI-SDM utterance groups; cols = estimated 0/1/2/3/4/≥5 talkers): WavLM-Large + Vicuna-7B LLM system — actual 1 → 0.0 / 96.7 / 3.2 / 0.1 / 0 / 0; actual 2 → 0.0 / 11.7 / 76.9 / 11.0 / 0.4 / 0. Conformer AED pre-trained on 900k h — actual 1 → 0.2 / 97.2 / 2.5 / 0.1; actual 2 → 0.0 / 13.7 / 80.5 / 5.9. WavLM AED — actual 1 → 92.1% correct, 7.6% estimated as 2; actual 2 → 73.0% correct. — [arXiv 2408.17431 Table 6](https://arxiv.org/html/2408.17431)
- [PAPER] t-SOT: "the t-SOT model achieved almost the same, and sometimes even better, WER compared to the single-talker ASR models for the single-talker evaluation set. This property is desirable to deploy one model for both single-talker and multi-talker application scenarios"; attributed to overlap acting as data augmentation "as long as the model has sufficient capacity". — [arXiv 2202.00842 §3.1.3](https://arxiv.org/html/2202.00842)
- [PAPER] Multilingual retention (Li et al., Microsoft, "Adapting Multi-Lingual ASR Models for Handling Multiple Talkers", arXiv 2305.18747; Whisper + SOT): "when we fine-tuned the entire Whisper model with the enhanced SOT method using English data, the obtained model performed poorly for other languages" / "naively fine-tuning the model with the English-only multi-talker data impairs the multi-lingual capability". Fix: freeze most of Whisper and train only bottleneck adapters (two per Transformer block, encoder and decoder), layer-norm parameters and "the token embedding for ⟨sc⟩". Table 3 (Whisper medium; AMI-SDM WER / AliMeeting Mandarin CER, zero-shot): original 44.0 / 59.1; full FT on AMI 23.6 / 50.7; adapter FT on AMI 25.0 / (improved, value truncated in extraction — see paper); adapter + 120 h simulated LibriSpeech 24.7 / 40.1; adapter + 360 h 24.3 / 36.9; reference full FT on AliMeeting itself 39.4 / 28.3. "the learned knowledge from English can be well transferred into Chinese multi-talker meetings." — [arXiv 2305.18747 §2.3, §3.5, Table 3](https://arxiv.org/html/2305.18747)
- [PAPER] Same paper, speaker counting of original (un-adapted) Whisper medium on AMI-SDM / AliMeeting: 100.0% of groups estimated as 1 talker regardless of the truth — a multilingual single-talker foundation model outputs only one stream until SOT-adapted. Simulated meeting-style data with 60–80% overlap ratio improved counting for 3–4 speakers. — [arXiv 2305.18747 Table 3, §3.1](https://arxiv.org/html/2305.18747)
- [SEARCH] A documented SOT failure mode as speaker count grows: "the same transcription is sometimes mistakenly repeated" (duplicate hypotheses), noted by later work. — [Hypothesis Clustering and Merging, arXiv 2409.15732](https://arxiv.org/pdf/2409.15732)
- [SEARCH] t-SOT can be forced into single-talker mode by zeroing the ⟨cc⟩ output probability. — [arXiv 2202.00842](https://arxiv.org/pdf/2202.00842)
- [CODE] SOT-Whisper: "The resulting SOT-Whisper system supports both single-speaker and two-speaker recognition, using `<|cc|>` as the serialized speaker separator token"; single-speaker rows are read directly from the `wav` column and two-speaker rows are mixed on the fly in the same training CSV; evaluation sets are `dev-clean-2mix`, `test-clean-2mix` *and* single-speaker `test-clean`. Training is full fine-tuning (`freeze_encoder: False`, `lr_whisper: 1e-5`, 1 epoch, batch 32 in `hparams/large.yaml`). — [Greg0124/SOT-Whisper-MultiSpeaker-ASR](https://github.com/Greg0124/SOT-Whisper-MultiSpeaker-ASR)
- [SEARCH] Chan & Lian (Computer Speech & Language 100, 101984, 2026): Whisper is given multi-speaker ability "through full-parameter fine-tuning with SOT"; more than 8,000 hours of synthetic mixtures controlling overlap conditions, speaker pairing and utterance-length distributions; "recognition performance consistently improves as both model size and dataset scale increase". Single-speaker and LibriSpeechMix WER values: Not Reported (paywalled; not in README). — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0885230826000471)
- [PAPER] MT-LLM (Meng et al., ICASSP 2025, arXiv 2409.08596) Table I, WER % on LibriSpeech 1-spk / LibriSpeechMix 2-spk / 3-spk: MT-LLM 2.3 / 5.2 / 10.2; SOT-Conformer 3.6 / 4.9 / 6.2; SALMONN-7B 2.4 / 32.9 / 45.9; D2V-Sidecar-DB – / 7.5 / 11.9. Training data: 2- and 3-talker mixtures simulated from LibriSpeech 960 h ("The start time for each talker is randomly sampled") "Combined with original single-talker corpora, the total training speech data amounts to ∼6.3K hours, with ∼10% containing German" (exact single:multi ratio Not Reported). Authors note SOT-Conformer "falls short in single-talker scenarios, indicating its specialization in multi-talker ASR impairs its single-talker performance", whereas MT-LLM keeps 2.3. — [arXiv 2409.08596 Table I, §III](https://arxiv.org/html/2409.08596)
- [SEARCH] Encoder-only talker-count routing (arXiv 2603.10587): an explicit Talker-Count Head predicts the number of talkers and selects the decoding branch. Talker-count accuracy: Not Reported. — [arXiv 2603.10587](https://arxiv.org/abs/2603.10587)
- [CODE] SOT-DiCoW exposes `data.empty_transcripts_ratio` (default 0.0) — a knob for the ratio of training samples with empty transcripts — and `dataset_weights` (the released config weights NOTSOFAR-train : NOTSOFAR-dev : AMI-SDM : Libri2Mix-both : Libri2Mix-clean = 3 : 1 : 3 : 1 : 1). — [BUTSpeechFIT/SOT-DiCoW README / configs](https://github.com/BUTSpeechFIT/SOT-DiCoW)
- [SEARCH] SA-DiCoW's two-phase training is described as helping "retain Whisper's original linguistic capabilities while adapting it to multi-talker scenarios". — [arXiv 2510.03723](https://arxiv.org/pdf/2510.03723)
- [CODE] Qwen3-ASR itself already has a learned "nothing here" output: `language None<asr_text>` for audio with no recognizable speech, taught with non-speech data in the SFT stage. — [Qwen3-ASR tech report PDF in repo](https://github.com/QwenLM/Qwen3-ASR/blob/main/assets/Qwen3_ASR.pdf)

### Inferences
- (Inference) The mechanism that prevents a hallucinated second speaker in SOT is purely data-driven: single-talker samples whose target ends without `<sc>`. None of the accessible sources reports a recommended single:multi ratio, so the ratio must be tuned empirically; track (a) single-talker CER/WER regression vs. the base model and (b) "false `<sc>` rate" on single-talker audio and "missed `<sc>` rate" on 2-talker audio as explicit metrics (speaker-counting accuracy in SOT terms).
- (Inference) For the multilingual requirement (Hokkien / Mandarin / English): Li et al. (2305.18747) is direct evidence that full fine-tuning on one language's SOT data damages the other languages, and that parameter-efficient adaptation (adapters + delimiter embedding) both preserves them and transfers multi-talker ability cross-lingually. This supports (a) LoRA/adapter-style tuning over full FT for the LLM side, and (b) including overlap mixtures *and* single-talker replay in all three languages rather than English/Mandarin only. No paper studies this for an LLM-based ASR model.
- (Inference) Removing single-talker data from SOT training is clearly harmful (SOT 2-speaker-only model: 16.7 WER on single-talker vs 5.7), so single-talker samples are mandatory, not optional.
- (Inference) The t-SOT trick (suppress the delimiter token's logit) transfers directly to an LLM decoder as a `bad_words_ids` / logit-bias switch, giving a guaranteed single-speaker mode at inference if a product needs it.

### Gaps
- Explicit single:multi sampling ratios: Not Reported in SOT (2003.12687), MT-LLM, or Chan & Lian. Shi et al. (LibriMix) and SOP train on 2-talker-only (or 3-talker-only) LibriMix, so they give no evidence on single-talker retention at all.
- The Exp. 11 AliMeeting CER (adapter, AMI only) in Li et al. Table 3 was truncated in text extraction; read the table before quoting.
- No source quantifying "hallucinated second speaker" rates for LLM-based SOT models was found.

## 4. How do papers address the model transcribing only the louder/dominant speaker (energy ratio / SIR augmentation, results by SIR)?

### Takeaway
None of the SOT / LLM-MT-ASR papers read reports WER by SIR or analyses "dominant-speaker-only" errors. The standard simulations mix utterances at their original volumes (≈0 dB average SIR in the SOT paper); the only level-related augmentation found is t-SOT's whole-mixture volume perturbation. Robustness to unequal loudness is therefore an evidence gap, not an established practice.

### Cited Findings
- [PAPER] SOT: "When mixing the audio signals, the original volume of each utterance was kept unchanged, resulting in an average signal-to-interference ratio of about 0 dB." — [arXiv 2003.12687 §5.1](https://arxiv.org/html/2003.12687)
- [PAPER] t-SOT: second utterance delayed by d ~ Uniform(0, len(u1)) and "mixed without changing the original volumes"; augmentation = speed perturbation {0.9, 1.0, 1.1}, "volume perturbation with the ratio between 0.125 to 2.0", adaptive SpecAugment; data simulated on the fly. — [arXiv 2202.00842 §3.1](https://arxiv.org/html/2202.00842)
- [PAPER] A grep of the full texts of 2408.17431, 2409.08596, 2509.04488, 2305.18747 and 2603.10587 for "SIR / signal-to-interference / energy / loud" found no SIR-stratified result or energy-ratio augmentation in any of them. — [arXiv 2408.17431](https://arxiv.org/html/2408.17431), [arXiv 2409.08596](https://arxiv.org/html/2409.08596), [arXiv 2509.04488](https://arxiv.org/html/2509.04488)
- [PAPER] SOP paper error analysis (CTC branch): "regions with high overlap, where multiple talkers produced CTC outputs at the same time step, or where frequent switching occurred between different talkers' CTC outputs across adjacent frames tended to result in more prediction errors." — [arXiv 2509.04488 §IV-E](https://arxiv.org/html/2509.04488)
- [SEARCH] A targeted search for SIR-stratified WER, weaker-speaker deletion errors and energy-ratio augmentation in SOT/LLM MT-ASR returned no paper reporting these. — (search result; closest hits: [arXiv 2509.04488](https://arxiv.org/pdf/2509.04488), [arXiv 2503.17886](https://arxiv.org/html/2503.17886), [Interspeech 2025 "Improving Practical Aspects of End-to-End Multi-Talker Speech Recognition"](https://www.isca-archive.org/interspeech_2025/subramanian25b_interspeech.pdf))
- [CODE] SOT-Whisper's released mixing function sums the two signals without any gain/SIR scaling (`mixed_signal = sig1 + sig2_delayed`); SIR control in the paper's 8,000-hour data pipeline: Not Reported in the repo. — [Greg0124/SOT-Whisper-MultiSpeaker-ASR mix_process.py](https://github.com/Greg0124/SOT-Whisper-MultiSpeaker-ASR/blob/main/mix_process.py)
- [SEARCH] DiCoW on NOTSOFAR-1 eval-small: 33.5% tcpWER (22.6% tcORC-WER) "with deletions as the main error type" — evidence that missed (deleted) speech is the dominant error on real overlapped meetings even with diarization conditioning. — [arXiv 2501.00114](https://arxiv.org/pdf/2501.00114)
- [SEARCH] "Mind the Gap" (Polok et al., arXiv 2605.15442; DiCoW, not SOT): synthetic conversational data modelling turn hold / turn switch / interruption / backchannel; "ASR benefits from 'difficult' overlapping examples", and a diverse synthetic mixture outperformed training on real conversational data alone for MT-ASR. — [arXiv 2605.15442](https://arxiv.org/abs/2605.15442)
- [SEARCH] Decoupled separation + ASR (arXiv 2503.17886) reports 5.1% WER on Libri2Mix dev/test by training the separator front-end and a clean-speech ASR back-end apart — an alternative when single-model SOT drops the weaker talker. — [arXiv 2503.17886](https://arxiv.org/html/2503.17886)
- [SEARCH] Chan & Lian's synthetic data "control overlap conditions, speaker pairing, and utterance-length distributions"; energy ratio is not mentioned in the abstract. — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0885230826000471)

### Inferences
- (Inference) Since the literature gives no recipe, the team should treat relative level as an explicit simulation variable (sample a per-mixture level difference) and report results in SIR buckets plus per-speaker deletion rate (first vs. second, louder vs. quieter), because aggregate WER hides "dominant-speaker-only" behaviour.
- (Inference) A cheap detector for dominant-speaker collapse is the missed-`<sc>` rate on known 2-talker test audio.

### Gaps
- Per-SIR results: Not Reported in any paper read. LibriMix's own loudness-sampling protocol was not checked.
- Whether Qwen3-ASR's AuT encoder (pretrained on ~40M hours pseudo-labelled single-stream ASR data) preserves weaker-talker information: no evidence found either way. The tech report only evaluates "multi-speaker Chinese conversational speech" (Dialog-*) as ordinary ASR, not overlap recovery.

## 5. Qwen3-ASR specifics (encoder, frame rate, projector, LLM, prompt template, special tokens, fine-tuning recipe, HF transformers exposure)

### Takeaway
Qwen3-ASR-0.6B = AuT encoder (18 layers, d=896, ~180M params, 128-bin Fbank, 3× stride-2 Conv2d = 8× downsampling → 12.5 Hz) + 2-layer MLP projector (896→896→1024) + Qwen3-0.6B decoder (28 layers, hidden 1024, vocab 151,936, tied embeddings); output is plain text `language X<asr_text>TEXT<|im_end|>` after a ChatML prompt whose system turn is free-text context. The official fine-tuning script is a full-parameter HF `Trainer` SFT script taking JSONL `{"audio","text"}` where `text` is the literal assistant target — so an SOT target is a data-only change, and the tokenizer already contains 27 placeholder tokens `<blank1>`–`<blank27>` (ids 151677–151703) that could serve as a speaker-change delimiter without resizing embeddings; LoRA is not in the official script (community forks exist), and the official script has two open, unfixed bug reports.

### Cited Findings

**Architecture**
- [CODE] "AuT is an attention-encoder-decoder (AED) based ASR model which conducts 8 times downsampling to Fbank feature with 128 dimensions, yielding a 12.5Hz token rate audio encoder. We use a dynamic flash attention window size ranging from 1s to 8s, which allows Qwen3-ASR to perform both streaming inference with short chunks and offline inference with long queries." — [Tech report (arXiv 2601.21337) PDF in repo, §2.1](https://github.com/QwenLM/Qwen3-ASR/blob/main/assets/Qwen3_ASR.pdf)
- [CODE] "Qwen3-ASR-1.7B is built with Qwen3-1.7B, a projector, and an AuT encoder with 300M parameters and 1024 hidden size." "Qwen3-ASR-0.6B is built with Qwen3-0.6B, a projector and an AuT encoder with 180M parameters and a hidden size of 896." — [Tech report §2.1](https://github.com/QwenLM/Qwen3-ASR/blob/main/assets/Qwen3_ASR.pdf)
- [CODE, third-party reverse-engineering of the released weights] 0.6B vs 1.7B: encoder d_model 896 vs 1024; encoder layers 18 vs 24; encoder output_dim 1024 vs 2048; decoder hidden 1024 vs 2048; decoder layers 28 vs 28; vocab 151,936 both; tied input/output embeddings (embed_tokens == lm_head); projector `GELU(Linear(d_model→d_model))` then `Linear(d_model→output_dim)` i.e. 896→896→1024 for 0.6B; Conv2D stem = 3 layers each stride 2 in time and frequency, then `Linear(7680→d_model)`; sinusoidal positions; windowed encoder attention. — [antirez/qwen-asr MODEL.md](https://github.com/antirez/qwen-asr/blob/main/MODEL.md)
- [CODE] HF transformers implementation: `Qwen3ASREncoder` has `conv2d1/2/3 = nn.Conv2d(..., 3, 2, padding=1)` with `downsample_hidden_size` 480, `n_window=50` (each conv chunk = 100 mel frames = 1 s at 10 ms hop), `n_window_infer=800` (8 s attention window); `Qwen3ASRMultiModalProjector` = `linear_1(d_model→d_model)` → activation → `linear_2(d_model→output_dim)`. Config class defaults correspond to the 1.7B checkpoint (encoder 24 layers / d_model 1024 / output_dim 3584-default-overridden-by-checkpoint; text_config hidden 2048, 28 layers). — [transformers configuration_qwen3_asr.py](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_asr/configuration_qwen3_asr.py), [modeling_qwen3_asr.py](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_asr/modeling_qwen3_asr.py)
- [CODE] Audio-token count: each full 1-s chunk (100 mel frames) yields 13 audio tokens (`(audio_lengths // chunk_len) * 13` plus the partial last chunk through three stride-2 convs) — i.e. nominal 12.5 Hz, 13 tokens per full second in practice. — [transformers processing_qwen3_asr.py `_get_audio_token_length`](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_asr/processing_qwen3_asr.py)
- [CODE] HF doc describes the model as "a Whisper-style audio encoder with a Qwen3 language model decoder"; the modeling file's intro string says "fine-tuned Whisper encoder, multi-modal projector, Qwen2 language model". Conflict with the tech report, which says AuT is pretrained separately (AED framework, ~40M hours pseudo-labelled data); the "Whisper" wording describes the encoder's code structure, not its weights' provenance. — [HF doc qwen3_asr.md](https://github.com/huggingface/transformers/blob/main/docs/source/en/model_doc/qwen3_asr.md) vs [Tech report §2.2](https://github.com/QwenLM/Qwen3-ASR/blob/main/assets/Qwen3_ASR.pdf)

**Training stages of the released model**
- [CODE] (1) AuT pretraining on ~40 million hours pseudo-labelled ASR data (mostly Chinese/English); (2) Omni pretraining (3 trillion tokens, same as Qwen3-Omni); (3) ASR SFT with multilingual data + "non-speech data, streaming-enhancement data and context biasing data", and "we train the model to be an ASR-only model that does not follow natural-language instructions in the prompt"; (4) RL with GSPO on ~50k utterances (35% zh/en, 35% multilingual, 30% functional). — [Tech report §2.2](https://github.com/QwenLM/Qwen3-ASR/blob/main/assets/Qwen3_ASR.pdf)

### Inferences
- (Inference) "SOT needs only a target change" is true at the *training-script* level: put `language X<asr_text>utt1<delim>utt2` in the JSONL `text` field; the official collator, loss and parser work unchanged, and `parse_asr_output` returns the delimiter inside `.text`.
- (Inference) Delimiter choices and their cost: (a) a plain-text delimiter already tokenizable by the Qwen BPE (e.g. a rare punctuation/string) needs no embedding change and is LoRA-friendly, but must not collide with real transcript text and may be split into several tokens; (b) a *new* special token needs `tokenizer.add_tokens` + `resize_token_embeddings`, and because input/output embeddings are tied and LoRA adapters leave the embedding matrix frozen, the embedding (and tied lm_head) row must be made trainable (e.g. PEFT `modules_to_save`/trainable-token mechanisms) and shipped with the adapter; (c) re-using one of the 27 existing `<blankN>` tokens (ids 151677–151703, verified in `tokenizer_config.json`) as the speaker-change delimiter needs *no* tokenizer change and *no* `resize_token_embeddings` (vocab stays 151,936); it is a single token that cannot collide with transcript text. Caveats (inference): whether the `<blankN>` rows were ever trained/used internally by Qwen is unknown, the row still has to be learned (so the embedding/tied lm_head row should be trainable even under LoRA — cf. Li et al. training only "the token embedding for ⟨sc⟩" alongside adapters), and — verified in `tokenizer_config.json` — `<blank1..27>` are flagged `special: true` whereas `<asr_text>` and `<non_speech>` are `special: false`; a `<blankN>` delimiter would therefore be *stripped* by any `skip_special_tokens=True` decode (the two utterances would be silently concatenated), so the decode path must use `skip_special_tokens=False` plus manual clean-up, or the delimiter must be a non-special token (`<non_speech>` is an existing non-special single token of unknown purpose; a newly added non-special token needs an embedding resize).
- (Inference) The `language X` header is a single tag per output; for a Mandarin+Hokkien or code-switched overlap the per-speaker language cannot be expressed in the stock format (the toolkit only merges per-*chunk* languages as "Chinese,English"). Since no Hokkien/Minnan tag exists (Minnan falls under `Chinese`), the team must decide whether to keep `language Chinese`, use `language None`, or force the language via prompt prefill.
- (Inference) The built-in repetition post-filter (`detect_and_fix_repetitions`) and the 512-token default cap could interact with SOT outputs (two speakers saying similar things; longer outputs) and should be reviewed.
- (Inference) The streaming design (prefix-continuation with token rollback) assumes the transcript grows monotonically at its end; utterance-level SOT violates this once the second speaker starts (speaker-1 text must still grow *before* the delimiter), so SOT-finetuned models should be assumed offline-only unless streaming is redesigned (this is exactly the problem t-SOT was invented for).
- (Inference) The SFT stage deliberately made the model ignore natural-language instructions in the prompt, so prompt-only control ("transcribe both speakers") cannot be expected to work zero-shot; behaviour must be taught by fine-tuning. A system-prompt *tag* could still be trained as a mode switch, but the simplest design is data-driven (no `<delim>` in single-talker targets).
- (Inference) Before any SOT experiment the two reported bugs in `qwen3_asr_sft.py` (label masking under left padding; loss scaling) should be checked/fixed, otherwise results (especially on short single-speaker vs long overlapped samples batched together) are not trustworthy.

### Inferences
- (Inference) Applying SOT to Qwen3-ASR would be novel public work; there is no reference recipe, hyper-parameter set, or known-good delimiter for this model family. The nearest transferable recipes are (i) SOT-Whisper for data/target design (single+2-speaker mix in one CSV, FIFO, on-the-fly mixing, delimiter token, full FT at lr 1e-5) and (ii) MT-LLM / Shi et al. for the LLM side (LoRA r=16–32 on decoder attention, trainable projector/adapter).
- (Inference) The most decision-relevant published result for a "LoRA on Qwen3-ASR" plan is Shi et al. Table 3: with an encoder that had not been adapted to overlapped speech, freezing it gave 47.8/46.7 WER versus 11.4/10.2 when it was trained — even though that encoder (WavLM) was itself pre-trained with overlapped speech. LoRA on the LLM, by contrast, was worth only ~1 WER point (Table 2). Qwen3-ASR's AuT encoder was pretrained as a single-stream ASR encoder on pseudo-labelled data (and un-adapted Whisper, a comparable model, counts 100% of AMI groups as one talker). So the encoder (and projector) should be expected to need adaptation — full encoder fine-tuning or LoRA/adapters *inside the audio encoder* — and "LLM-only LoRA" should be treated as a baseline likely to under-perform, to be verified by an explicit frozen-vs-trainable-encoder ablation. The official script's full-parameter default and SOT-Whisper's `freeze_encoder: False` point the same way; MT-LLM's frozen-encoder success relied on a *second* (WavLM) encoder plus trainable adapters, and still trailed on 3 speakers.
- (Inference) Tension to manage: adapting the encoder is what the overlap evidence favours, while Li et al. (2305.18747) show full fine-tuning erodes other languages. Parameter-efficient adaptation of both encoder and LLM plus multilingual single-talker replay is the combination consistent with both findings; no paper tests this on an LLM-ASR model.
- (Inference) Frame-rate note: Shi et al. fed the LLM 5 Hz speech embeddings and SOT still worked for 2 talkers, so Qwen3-ASR's 12.5 Hz is not obviously a bottleneck for 2-talker SOT; the SOP authors do blame down-sampling/projection for 3-talker failures.
- (Inference) Published evidence that plain SOT + LLM works well for 2 talkers but degrades for 3 (SOP paper; 2603.10587) is favourable for this project's 2-talker scope.
