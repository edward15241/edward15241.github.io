## KQ1. Hao Shi et al.: SLT 2024 "Serialized Speech Information Guidance with Overlapped Encoding Separation" (EncSep/GEncSep) and ASRU 2025 "Serialized Output Prompting" (SOP) — papers + code

### Takeaway
The design is: speech encoder → (a) downsample+projector → LLM prefix for SOT, and (b) a small LSTM **Separator** on the *pre-downsampling* encoder states that splits them into N streams, each supervised by its own CTC head with **fixed (non-PIT) speaker order = the SOT order**; in SOP the greedy CTC transcripts of the streams are embedded with the LLM's own token-embedding table and **prepended as a text prompt** to the mixed-speech embeddings. So in SOP the separator and CTC heads **are required at inference**; a pure "aux-loss, drop at inference" configuration exists in code (`hybrid` mode without `ctc_bridge`) and corresponds to the papers' "SOT-CTC"/EncSep-style variants, which the papers report as helping only modestly (SLT) or even degrading (ASRU stage-2). The most decision-relevant published number: with a 1B LLaMA, **encoder-only serialized CTC gets 20.5% WER on noisy Libri3Mix vs 32.3% for LLM-SOT (but 10.1% vs 9.1% on Libri2Mix)** — i.e. for 3 talkers the encoder+separator demonstrably holds information the LLM-SOT decoder fails to use.

**Papers (identity / claims)**

**Code (all [code-verified] unless tagged; repo README says it implements both papers)**
- Repo scope: WavLM (`microsoft/wavlm-large`) front-end + LLaMA-3.2-1B / 3.2-3B / 3.1-8B (base and Instruct) decoder; LibriMix 2mix/3mix clean and noisy; "A single audio mixture … is encoded by a WavLM front-end. An optional separator splits encoder features into N per-speaker streams supervised by per-speaker CTC heads. A LLaMA decoder generates all N transcriptions as one serialized token sequence, separated by a `<sc>` token." — [README](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/README.md)
- **Separator architecture** (`models/separator.py`): `Linear(in_dim→H) + ReLU + LayerNorm` → **2-layer unidirectional LSTM** (hand-written `CustomLSTMCell`, hidden H, per-step dropout 0.2, python loop over T) → `LayerNorm(H)` → **N parallel branches**, each `Linear(H→H) + ReLU + Linear(H→in_dim) + ReLU + LayerNorm(in_dim)`. Output: list of N tensors (B, T, in_dim). It is a feature *mapper* (not a mask multiplied onto the input). A tiny bias offset (`1e-3 * branch_index`) breaks symmetry between branches at init. — [separator.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/separator.py)
- **Separator size [computed from code]**: `separator_hidden` default is 796 in `run.sh` (896 in `src/arguments.py`); `in_dim = config.encoder.output_hidden_size` (1024 for WavLM-Large). With H=796: **13,868,484 params for 2 talkers; 15,321,072 for 3 talkers**. With H=896: 17,222,784 / 18,947,072. The papers' own stated parameter count: **Not Reported — not retrievable.** — [run.sh L80](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/run.sh), [arguments.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/src/arguments.py)
- **CTC heads**: one ESPnet-style `CTC` module per talker (`serialized_ctc = ModuleList`), each a single `Linear(1024 → decoder.vocab_size+1)` — i.e. the CTC vocabulary is the **LLM's own BPE vocabulary plus a blank** (blank id = last index). [computed/inference] With LLaMA-3 vocab (code default `blank_id=128258`) each head is ≈ 1025 × 128,259 ≈ **131M parameters**, i.e. the CTC heads are ~10× larger than the separator; using the LLM tokenizer is what allows CTC output ids to be fed straight into the LLM embedding table. — [modeling_speech_encoder_decoder_llama.py L177–192](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/modeling_speech_encoder_decoder_llama.py), [ctc.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/ctc.py)
- **Where the separator taps**: `encoder_outputs[1]` = WavLM transformer output **before** the conv downsampling adapter (20 ms frames); the LLM instead gets `encoder_outputs[0]` = adapter-downsampled output projected by `enc_to_dec_proj` (a single `Linear(enc_hidden → llm_hidden)`). So CTC runs at full frame rate while the LLM sees a low-frame-rate *mixed* stream. — [glue model L553–568](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/modeling_speech_encoder_decoder_llama.py)
- **CTC target assignment = fixed order, NOT PIT.** The SOT label sequence is split at `<sc>` into N segments (`split_k_speakers_and_lengths`), and head *i* is trained on segment *i*. `losses.py` header comment: PIT infrastructure "was removed because it had been unreachable… `do_pit = False` was hardcoded… the `use_pit` constructor flag was never set to True… The CTC supervision now uses fixed-order assignment (head i ↔ speaker i in the dataset's split order)." So the published results were obtained with FIFO/serialized order, not PIT. — [losses.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/losses.py), [split_labels_by_sc.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/utils/split_labels_by_sc.py)
- **Hybrid loss**: `total = alpha * CE_attention + (1 - alpha) * mean_over_heads(CTC_i)`, `alpha = ctc_alpha`, default **0.7** (note: despite the name, `ctc_alpha` is the weight of the **attention/CE** term; CTC gets 0.3). `train_mode ∈ {attention, ctc, hybrid}` selects the active terms. CTC is computed in fp32 with `zero_infinity=True`. An optional PCGrad projection of per-speaker CTC gradients on shared params exists (`pcgrad` flag, default False). — [losses.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/losses.py), [arguments.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/src/arguments.py)
- **Stage 1 (SOT) recipe in code** (`scripts/sot_submit_1b.sh`): `train_mode=attention`, `talker_ctc=false`, **`encoder_freeze=false` (WavLM transformer fine-tuned; only the CNN feature extractor frozen by default)**, `adapter_only_decoder=true` (LoRA r=16, α=32, dropout 0.1 on decoder `q/k/v/o_proj`; LLM base weights frozen), plus `partial_decoder_unfreeze="lm_head,embed_tokens,…"` and `enc_to_dec_proj` trainable; lr 3e-5, warmup 400. LoRA is merged into base weights after training. The checkpoint directory names used later (`wavlm-Llama-3.2-1B-encoder_unfreeze-decoder_freeze-adater_decoder-…`) confirm the SOT baseline was trained with the **encoder unfrozen**. — [sot_submit_1b.sh](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/scripts/sot_submit_1b.sh), [insert_adapter_decoder.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/src/insert_adapter_decoder.py), [unfreeze_utils.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/utils/unfreeze_utils.py)
- **Stage 2 (separator + CTC) recipe in code** (`scripts/ctc_submit_1b.sh`): starts from the stage-1 SOT checkpoint, `train_mode=ctc`, `encoder_freeze=true`, no LoRA, `partial_others_unfreeze="separator,serialized_ctc"` → **only the separator and CTC heads are trained on top of the frozen, SOT-adapted WavLM**. A commented-out alternative (`train_mode=hybrid`, `ef=false`) shows the joint CTC+CE variant. README table: `ctc` mode = "Pre-train separator before LLM fine-tuning"; `hybrid` = "α·CE + (1-α)·CTC … Main training recipe". (This CTC-only/frozen-encoder script differs slightly from the paper-extract wording "Stage 2 trains the encoder/separator/CTC branches with a CTC+CE loss" — both variants exist in code; which one produced the published tables is **not verifiable here**.) — [ctc_submit_1b.sh](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/scripts/ctc_submit_1b.sh), [README](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/README.md)
- **Stage 3 (SOP) in code** = `ctc_bridge=true, ctc_bridge_type="ctcprompt"`, commented in source as "ASRU 2025 proposed method: concat ctc transcription embedding + mixed encoding": for each head, `argmax` → collapse repeats/remove blank → token ids; ids of all heads concatenated in head order → embedded with the **LLM's `embed_tokens`** → `encoder_hidden_states = cat([ctc_prefix_embeds, mixed_speech_embeds])`. The LLM therefore sees `[CTC-hypothesis text of talker 1 … talker N] + [original mixed speech embeddings]` and then generates the SOT string. Separator and CTC heads run at inference; cost = one extra LSTM pass + N linear layers + extra prompt tokens (no extra LLM pass). — [glue model L624–660](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/modeling_speech_encoder_decoder_llama.py), [ctc_prompt.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/ctc_prompt.py)
- **Other feeding variants present in code**: (i) `ctc_bridge_type="raw"`: the N separated streams are **concatenated along time**, passed through the same downsampling adapter + `enc_to_dec_proj`, and **replace** the mixed features as the LLM prefix (GEncSep-style "concatenate separated encodings"); (ii) `ctc_bridge_type="softmax"` (`CTCPerSpeakerExtractorConcatSoftmax`) with the in-code comment "Currently help for 2-talker, but no significant improment for 3-talker"; (iii) `decoder_cross_attention=true` with `decoder_cross_attention_feature ∈ {mix, sep}`: per-layer (gated / adaptive-rank-LoRA) cross-attention adapters inside LLaMA attending to raw WavLM or time-concatenated separated features (the 2603.27205 method); (iv) `talker_ctc_refine` (CTC-aware frame refiner). — [glue model L600–660](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/modeling_speech_encoder_decoder_llama.py), [README flags](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/README.md)

### Inferences
- [inference] The authors never train WavLM-frozen-from-pretraining for SOT in the shipped recipes: stage 1 fine-tunes the WavLM transformer jointly with LLM-LoRA. So their results do **not** answer "can a frozen single-talker encoder support two-talker SOT"; they answer "after SOT fine-tuning of the encoder, a 14M-param LSTM + linear CTC heads on the frozen encoder can read out each talker separately".
- [inference] The stage-2 design (freeze SOT-adapted encoder, train only separator + per-talker CTC, decode with CTC alone) is literally a probing experiment: per-talker CTC WER of the frozen encoder is an upper-bound-style measurement of what linguistic content per talker is linearly/LSTM-recoverable from the encoder. The 3-mix result (20.5 CTC-only vs 32.3 LLM-SOT) is direct published evidence of a **decoder/interface-side** failure in 3-talker conditions: the information was in the encoder states, and the prefix-conditioned LLM did not exploit it.
- [inference] In the 2-talker case the same comparison (10.1 CTC-only vs 9.1 LLM-SOT, noisy) says the LLM-SOT path is already slightly better than the encoder-only read-out, i.e. for 2 talkers neither the paper nor the code suggests a large decoder-side deficit once the encoder is SOT-fine-tuned; this matches the SLT finding of no EncSep gain on clean Libri2Mix.
- [inference] Fixed-order CTC works here because LibriMix SOT labels have a deterministic order and the separator is trained to follow it; with fully synchronous starts (LibriMix "min/max" mixtures start all talkers at t≈0) "start-time order" is weakly defined, which may be one reason the authors once scaffolded PIT/PCGrad and gradient-conflict debugging and report the hybrid stage degrading.
- [inference] SOP's injection format (CTC hypothesis **text tokens** + untouched mixed speech embeddings) is the least invasive option for an encoder→projector→LLM stack: it changes nothing in the projector pathway and leaves the LLM the option to ignore a wrong hypothesis.

## KQ2. Other multi-speaker encoder-side designs (PIT multi-output, Sidecar, Graph-PIT, HEAT/SURT, SACTC, Cocktail HuBERT, WavLM utterance mixing)

### Takeaway
Three families exist: (1) **in-encoder separators with multi-branch output + PIT** (Sidecar on wav2vec2/Whisper; SURT mask encoder with HEAT) that keep the single-talker model frozen and run the upper encoder + decoder once per talker; (2) **single-stream SOT with a CTC auxiliary** (SOT-CTC, Speaker-Aware CTC, Speaker-Distinguishable CTC) where CTC shapes the encoder and can be dropped at inference; (3) **mixture-aware pretraining** (WavLM utterance mixing, Cocktail HuBERT) which determines whether the encoder was ever trained to represent a second talker.

### Cited Findings
- **Sidecar separator (Meng et al., ICASSP 2023, arXiv 2302.09908).** A well-trained single-talker ASR (wav2vec 2.0-based) is frozen; a Conv-TasNet-style temporal convolutional separator ("Sidecar") is inserted between two encoder layers (rationale: lower layers carry more acoustic, upper more linguistic information); only the Sidecar is trained: **8.7 M params = 8.4% of all parameters**. Results: **WER 10.36% on 2-speaker LibriMix** (large margin over previous SOTA at the time), and 7.56% on LibriSpeechMix with limited training. [search-extract] — [arXiv 2302.09908](https://arxiv.org/pdf/2302.09908), [CUHK PDF](https://www1.se.cuhk.edu.hk/~hccl/publications/pub/ICASSP2023_Sidecar_final_hyper.pdf), [IEEE](https://ieeexplore.ieee.org/document/10095295/)
- **Sidecar + diarization (Meng et al., Interspeech 2023, arXiv 2305.16263).** Adds a diarization branch to the Sidecar "with a negligible overhead of only 768 parameters". Results table: **Not Reported — not retrievable.** [search-extract] — [arXiv 2305.16263](https://arxiv.org/pdf/2305.16263)
- **Whisper + Sidecar + Target Talker Identifier (Meng et al., Interspeech 2024, arXiv 2407.09817).** Whisper weights are **frozen**; a Sidecar separator (stacked 1-D dilated conv blocks, Conv-TasNet-inspired) is plugged into the Whisper **encoder after the second encoder block** to separate the mixed embedding into per-talker embeddings; a Target Talker Identifier uses a 3-second enrollment cue (80% multi-talker / 20% target-talker training mix); **soft prompt tuning** on the decoder; permutation-invariant ASR loss. Results [search-extract]: Whisper-large-SS-TTI **4.66% WER on Libri2Mix-type 2-talker and 16.79% on 3-talker**, vs 9.69 / 33.91 for the earlier D2V-Sidecar-DB; performance improves monotonically small → medium → large. Authors note that long soft prompts were hard to optimise "given the original Whisper model is frozen". Trainable-parameter count for the Whisper version: **Not Reported — not retrievable.** — [arXiv 2407.09817](https://arxiv.org/pdf/2407.09817), [ISCA PDF](https://www.isca-archive.org/interspeech_2024/meng24c_interspeech.pdf)
- **SURT + HEAT (Lu, Kanda, Li, Gong, IEEE SPL 2021, arXiv 2011.13148).** Streaming Unmixing and Recognition Transducer: RNN-T backbone, two encoder variants (speaker-differentiator encoder; **mask encoder**), two output channels. **HEAT (Heuristic Error Assignment Training)** = a simplified PIT that picks a single label assignment from heuristic information (e.g. start-time order) — "consumes much less memory, and is more computationally efficient" and "can achieve better accuracy compared with PIT" on LibriSpeechMix; SURT with ~120–150 ms algorithmic latency compares favourably with an offline seq2seq baseline. Absolute WER table: **Not Reported — not retrievable** (a third-party page lists 7.2 WER on LibriSpeech2Mix, unverified). [search-extract] — [arXiv 2011.13148](https://arxiv.org/abs/2011.13148), [Microsoft Research](https://www.microsoft.com/en-us/research/?p=712249)
- **Graph-PIT (von Neumann et al., Interspeech 2021, arXiv 2107.14446).** Recasts utterance-to-output-channel assignment as graph colouring so that only the **max number of concurrently active speakers** (not total speakers) must fit the number of output channels; a generalisation of uPIT aimed at continuous (meeting-length) separation; better WER than uPIT in follow-up LibriCSS experiments. It is a separation/assignment loss, relevant when a 2-output model must handle >2 speakers over long audio. [search-extract] — [arXiv 2107.14446](https://arxiv.org/pdf/2107.14446), [ISCA](https://www.isca-archive.org/interspeech_2021/neumann21_interspeech.html), [code](https://github.com/fgnt/graph_pit)
- **Speaker-Aware CTC (Kang, Meng, Cui, … H. Meng; ICASSP 2025, arXiv 2409.12388).** Analysis finding: "CTC guides the encoder to represent different speakers in distinct temporal regions of acoustic embeddings" in SOT-CTC models. SACTC (built on Bayes-risk CTC) adds a speaker-aware risk that penalises CTC paths mixing speakers, constraining the encoder to emit each speaker's tokens at specific frames. **SOT-SACTC consistently outperforms standard SOT-CTC across overlap degrees**; absolute numbers **Not Reported — not retrievable.** The CTC branch is an auxiliary loss on a single-stream encoder (no separator). [search-extract] — [arXiv 2409.12388](https://arxiv.org/abs/2409.12388), [code](https://github.com/kjw11/Speaker-Aware-CTC)
- **Speaker-Distinguishable CTC (arXiv 2506.07515).** Extends the idea by assigning a speaker label together with a token to each frame. Results **Not Reported — not retrievable.** [search-extract] — [arXiv 2506.07515](https://arxiv.org/html/2506.07515)
- **WavLM utterance mixing (Chen et al., arXiv 2110.13900).** Pre-training adds unsupervised simulated overlapped/noisy utterances "to force the model to deal with multi-speaker signals"; the main-speaker's pseudo-labels are the target; overlap region kept **< 50%**; mixing probability 0 for Base, 10% for Base+/Large; ablation removing mixing hurts speaker-related tasks most; the paper notes "HuBERT model is rarely optimized with speaker-overlapped speech and lacks multi-speaker modeling during pre-training". [search-extract] — [arXiv 2110.13900](https://arxiv.org/html/2110.13900v5), [HF model card](https://huggingface.co/microsoft/wavlm-large)
- **Cocktail HuBERT (Fazel-Zarandi & Hsu, ICASSP 2023, arXiv 2303.11131).** Masked pseudo-source-separation pre-training on mixtures (predict units of **all** sources); abstract claims **69% lower WER on multi-speaker ASR** and 31% lower DER vs prior SOTA SSL models, competitive on single-speaker SUPERB tasks. Absolute LibriMix WERs **Not Reported — not retrievable.** [search-extract; abstract-level] — [ResearchGate abstract](https://www.researchgate.net/publication/374947491_Cocktail_Hubert_Generalized_Self-Supervised_Pre-Training_for_Mixture_and_Single-Source_Speech)
- **Decoupled separation → ASR (Yang, Taherian, Kalkhorani, Wang; arXiv 2503.17886).** Opposite philosophy (waveform separation front-end + clean-trained ASR back-end); SOTA on Libri2Mix / SMS-WSJ / LibriCSS reported. Out of scope for the team (they exclude waveform separation) but it is the strong cascade baseline. [search-extract] — [arXiv 2503.17886](https://arxiv.org/abs/2503.17886)

### Inferences
- [inference] Sidecar results are the strongest "frozen single-talker model" evidence: with the **entire Whisper/wav2vec2 frozen**, a small separator placed after encoder block 2 suffices for 4.66% (2-talker) WER. This shows (a) the *early* encoder layers of a single-talker model still carry both talkers' acoustics, and (b) the frozen upper encoder layers + frozen decoder can process each separated stream — but each stream is processed **separately** (N passes through upper encoder + decoder), so it does **not** show that the top-layer output of an unmodified frozen encoder keeps both talkers.
- [inference] Sidecar-style inference cost ≈ lower layers once + (upper encoder layers + decoder) × N talkers; SOT-with-aux-CTC cost ≈ unchanged single pass; SOP cost ≈ single pass + separator/CTC + longer prompt.
- [inference] Fixed-order assignment (HEAT, Shi's serialized CTC) is repeatedly reported equal or better than PIT and much cheaper; PIT remains necessary only when no canonical order exists (Sidecar uses PIT because its output branches are unordered).

### Gaps
- "GEncSep" as a separately named model outside the SLT 2024 paper, "Serialized CTC"/"overlap-aware CTC" under those exact names, and multi-turn/"surround" RNN-T: no additional primary sources were retrieved in this session (BA-SOT arXiv 2305.13716, SA-SOT arXiv 2403.02010 and SC-SOT arXiv 2506.12672 surfaced only as titles).

## KQ3. NVIDIA Multitalker Parakeet Streaming 0.6B / "Speaker Targeting via Self-Speaker Adaptation" (speaker-kernel injection), META-CAT, DiCoW and variants

### Takeaway
These are **diarization-conditioned target-speaker encoders**: the ASR encoder is told, frame by frame, who is speaking (by Sortformer/diarizer activity), and one encoder(+decoder) pass is run **per speaker**. They handle full overlap well but **require an external diarizer and N passes**, which conflicts with the team's "no diarization" scope; they are relevant mainly as evidence that conditioning the *encoder* (not the decoder) is what makes fully-overlapped speech tractable.

### Cited Findings
- **Paper**: Weiqing Wang, Taejin Park, Ivan Medennikov, et al. (NVIDIA), "Speaker Targeting via Self-Speaker Adaptation for Multi-talker ASR", arXiv 2506.22646 (27 Jun 2025, rev. 29 Aug 2025), Interspeech 2025. Self-speaker adaptation for streaming multi-talker ASR **without speaker queries or enrollment audio**: speaker-specific kernels are generated from **speaker-wise activity predictions ("speaker supervision activations")** and injected into selected ASR encoder layers — per the extract, at the **pre-encode layer of the FastConformer encoder** — enabling "instantaneous speaker adaptation to target speakers while handling fully overlapped speech even in a streaming scenario". Backbone: cache-aware streaming FastConformer Transducer. Diarizer: streaming Sortformer. [search-extract] — [arXiv 2506.22646](https://arxiv.org/abs/2506.22646), [arXiv HTML](https://arxiv.org/html/2506.22646)
- **System size (paper)**: 238M total = FastConformer Transducer ASR 114M + Sortformer diarizer 123M + **speaker injection module 1.1M**. Separate kernels are used for each speaker (target vs. the other) in two-speaker mixtures. [search-extract] — [arXiv 2506.22646](https://arxiv.org/pdf/2506.22646)
- **Results (snippet-level, unverified against tables)**: cpWER 4.0% (1-mix) and 5.6% (2-mix) at 560 ms latency; experiments cover up to 3 speakers. Exact kernel equations, training-data composition and latency table: **Not Reported — not retrievable.** [search-extract] — [arXiv 2506.22646](https://arxiv.org/pdf/2506.22646), [ResearchGate](https://www.researchgate.net/publication/393183013_Speaker_Targeting_via_Self-Speaker_Adaptation_for_Multi-talker_ASR)
- **Model card `nvidia/multitalker-parakeet-streaming-0.6b-v1`**: streaming multitalker ASR "based on the Nemotron-Speech-Streaming model" (FastConformer / RNNT tags, 0.6B params); "takes only speaker diarization outputs as external information"; "**requires deploying one model instance per speaker**"; usage example pairs it with `diar_streaming_sortformer_4spk-v2` / `-v2.1` and `att_context_size=[70,13]`; one README revision states **latency 1.12 s with 13+1 lookahead frames**; trained on "a large combination of real conversations and simulated audio mixtures" (card lists 21 datasets; names not retrieved); evaluation table (diarizer = Streaming Sortformer v2): **AMI IHM 21.26, AMI SDM 37.44, CH109 15.81, Mixer 6 23.81** (metric label not visible in the extract — presumably cpWER, unverified). - **META-CAT (arXiv 2409.12352, ICASSP 2025, NVIDIA)**: end-to-end multi-talker framework for both multi-speaker and target-speaker ASR that masks ASR encoder activations with the output of a pre-trained diarization module (Sortformer) and concatenates the speaker-specific versions ("meta-information concatenation"). Noted drawback (from a later paper): depends on accurate diarization; activity errors propagate into recognition. Numbers **Not Reported — not retrievable.** [search-extract] — [arXiv 2409.12352](https://arxiv.org/abs/2409.12352), [IEEE](https://ieeexplore.ieee.org/document/10889841/)

One pass per target speaker. DiCoW v3.3 reports ~50% relative tcpWER reduction on Libri3Mix vs v1; SE-DiCoW (arXiv 2601.19194) adds self-enrollment by cross-attention and moves FDDT before positional embeddings. [search-extract] — [arXiv 2501.00114](https://arxiv.org/pdf/2501.00114), [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S088523082500066X), [HF BUT-FIT/DiCoW_v3_3](https://huggingface.co/BUT-FIT/DiCoW_v3_3), [HF BUT-FIT/SE-DiCoW](https://huggingface.co/BUT-FIT/SE-DiCoW)
- **DiCoW → end-to-end SOT (Kocour et al., arXiv 2510.03723)**: speaker-attributed Whisper that uses the DiCoW encoder to extract speaker-specific representations and combines them with SOT in one decoder; two-phase training (Whisper encoder+decoder frozen in phase 1) trained on English multi-talker data only; surpasses DiCoW on multi-talker mixtures such as LibriMix, while authors note performance drops on fully-overlapped LibriMix. Still requires diarization input. [search-extract] — [arXiv 2510.03723](https://arxiv.org/pdf/2510.03723)

### Inferences
- [inference] None of the NVIDIA/DiCoW/META-CAT systems is diarization-free: all take frame-level speaker-activity as input; "no enrollment" ≠ "no diarization". A diarization-free analogue for the team would be a *learned* in-encoder split (Sidecar / Shi's separator) rather than activity-conditioned kernels.
- [inference] The 1.1M-parameter injection module (vs 114M ASR) shows that a very small encoder-side conditioning signal is enough to steer a single-talker-style encoder toward one of two fully-overlapped talkers — consistent with the Sidecar evidence that the lower encoder still contains both talkers and that the deficit of single-talker models is *selection*, not *presence*, of information.

## KQ4. Does the encoder retain the second speaker? Probing studies and frozen-encoder vs fine-tuned-encoder ablations for multi-talker Speech-LLMs

### Takeaway
I found **no dedicated layer-wise probing paper** that measures second-speaker *content* in Whisper/WavLM/HuBERT (or Qwen-style) encoder outputs under overlap; the evidence is indirect but fairly consistent: (i) MT-LLM gets 5.2% WER on 2-speaker mixtures with **both encoders frozen** (Whisper-large-v2 + WavLM) and only adapters + LLM-LoRA trained, so frozen large encoders do retain enough for two talkers; (ii) Tencent's WavLM+LLM SOT study finds a frozen encoder that was **not** adapted to the mixture domain performs poorly, while an SOT-fine-tuned-then-frozen encoder is best; (iii) Shi et al.'s CTC-only read-out beats LLM-SOT in the 3-talker case, a decoder/interface-side failure. The field's own diagnostic tool for "encoder vs decoder" is exactly a per-talker CTC/separator read-out on the frozen encoder.

### Cited Findings
- **Direct probing: none found.** Searches for layer-wise probing of Whisper/WavLM/HuBERT on overlapped speech returned only probing work on other attributes (dysarthria, accents, paralinguistics, consonant clusters) and overlap *detection* studies; no study probing both speakers' lexical content. (Negative result of this session's searches; e.g. overlapped-speech **detection** with WavLM features outperforming MFCC: 63.4% vs 52.4% with a TCN.) — [Lebourdais et al., Interspeech 2022](https://www.isca-archive.org/interspeech_2022/lebourdais22_interspeech.pdf)
- **MT-LLM (Meng et al., arXiv 2409.08596, ICASSP 2025).** Encoders: Whisper-large-v2 encoder + WavLM-base, "All parameters of above models are frozen"; adapters per encoder = two conv layers (temporal downsampling) + bottleneck adapter + linear; LLM = Llama-2-chat-7b with LoRA rank 32; total 7.55B params, **76.6M (1%) trainable**. Results (main table, WER %): **1-talker 2.3, 2-speaker 5.2, 3-speaker 10.2** on English LibriSpeech-based mixtures (German: 11.7 / 21.0 / 22.8); SALMONN-7B in the same table: 32.9 (2-spk), 45.9 (3-spk). [search-extract] — [arXiv 2409.08596](https://arxiv.org/pdf/2409.08596), [code](https://github.com/cuhealthybrains/mt-llm)
- **"Advancing Multi-talker ASR Performance with LLMs" (Tencent AI Lab, arXiv 2408.17431, SLT 2024).** Encoder (WavLM-Large-based) + projector + Vicuna-7B, SOT. Multi-stage: first only the projector is trained with encoder and LLM frozen; LoRA on the LLM later. Table 3 studies freezing the encoder, comparing an encoder **not fine-tuned on LibriMix** with one **first fine-tuned on LibriMix with the AED (SOT) method**. Findings [search-extract of paper text + summaries]: if the encoder was not first fine-tuned on LibriMix, freezing it "performs poorly"; initialising from the LibriMix-fine-tuned encoder gives the best results, and that encoder "already has excellent representation extraction capabilities on LibriMix" so freezing it is as good as / better than continued joint training; LoRA consistently helps. Headline: **9.0% test WER (LLM system) vs 9.2% (AED baseline)** on LibriMix; AMI cpWER 20.4% (third-party summary, unverified). Table 3 numbers themselves: **Not Reported — not retrievable.** — [arXiv 2408.17431](https://arxiv.org/pdf/2408.17431), [IEEE](https://ieeexplore.ieee.org/document/10832362/), [emergentmind summary](https://www.emergentmind.com/papers/2408.17431)
- **CMT-LLM (He et al., Interspeech 2025, arXiv 2506.12059).** Same recipe: WavLM-Large fine-tuned with conventional SOT, then **frozen**; only projector trained + LoRA on Vicuna-7B; reports 7.3% WER on LibriMix vs 9.2% for its LLM baseline and 32.9% vs 34.2% on AMI-SDM (with contextual biasing, so not directly comparable). [search-extract] — [ISCA PDF](https://www.isca-archive.org/interspeech_2025/he25_interspeech.pdf), [arXiv 2506.12059](https://arxiv.org/html/2506.12059)
- **Shi et al. (see KQ1).** SOT baseline trained with WavLM **unfrozen** + LLM LoRA [code-verified]; then with the encoder frozen, a 14M separator + CTC heads read out each talker. Encoder-only serialized CTC 10.1 / 20.5 vs LLM-SOT 9.1 / 32.3 WER on noisy Libri2Mix / Libri3Mix (1B-Instruct). [search-extract] — [arXiv 2603.27205](https://arxiv.org/html/2603.27205), [ctc_submit_1b.sh](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/scripts/ctc_submit_1b.sh)
- **Frozen Whisper + Sidecar (KQ2).** Entire Whisper frozen; separator after encoder block 2; 4.66% (2-talker) / 16.79% (3-talker) WER. [search-extract] — [arXiv 2407.09817](https://arxiv.org/pdf/2407.09817)
- **Frozen Whisper + prompt tuning for target-speaker ASR (Ma et al., ICASSP 2024, arXiv 2312.08079).** Whisper kept frozen; trainable soft prompts (encoder and decoder side, "deep prompting") + target-speaker embedding steer it to transcribe one talker in overlapped speech; a secondary summary reports >60% WER reduction vs zero-shot Whisper on overlapped speech (unverified). [search-extract] — [arXiv 2312.08079](https://arxiv.org/html/2312.08079v2), [code](https://github.com/Aisaka0v0/TS-Whisper)
- **Whisper's encoder is not interference-invariant (Gong et al., Whisper-AT, Interspeech 2023, arXiv 2307.03183).** "Whisper is very robust against real-world background sounds…, but its audio representation is actually not noise-invariant, but is instead highly correlated to non-speech sounds" — the model recognises speech *conditioned on* the noise type; a frozen-Whisper audio tagger built on these representations is strong. Evidence that weakly-supervised ASR encoders do keep non-target acoustic content in their representations (shown for non-speech sounds, not for a competing talker). [search-extract] — [arXiv 2307.03183](https://arxiv.org/pdf/2307.03183), [code](https://github.com/yuangongnd/whisper-at)
- **Pre-training matters**: WavLM was pre-trained with <50%-overlap utterance mixing and main-speaker targets; HuBERT was not; Cocktail HuBERT explicitly predicts all sources (KQ2). — [arXiv 2110.13900](https://arxiv.org/html/2110.13900v5)
- **SOT-CTC encoder analysis**: in SOT-CTC models "CTC guides the encoder to represent different speakers in distinct temporal regions of acoustic embeddings" (visualisation-based finding). — [arXiv 2409.12388](https://arxiv.org/abs/2409.12388)

### Inferences
- [inference] How the literature separates "decoder hasn't learned two sentences" from "encoder lost speaker 2": (a) **encoder-only read-out** — freeze the encoder, train a small separator + per-talker CTC (Shi stage 2) or a Sidecar and measure per-talker WER; if the read-out WER ≤ the LLM-SOT WER, the bottleneck is downstream of the encoder; (b) **freeze ablations** — frozen-pretrained vs SOT-fine-tuned-then-frozen vs jointly trained encoder (Tencent Table 3); (c) **tap-point ablations** — Sidecar after layer 2 vs later, and Shi's tap *before* the temporal downsampling adapter, which separates "information lost in upper layers" from "lost in the downsampler/projector".
- [inference] For Qwen3-ASR-0.6B specifically, the closest published analogue to "freeze the audio encoder, LoRA only the LLM" is MT-LLM (works for 2 talkers with frozen Whisper-large-v2 + WavLM and a 7B LLM) and the Tencent "not fine-tuned + frozen = poor" result (WavLM-Large). These two disagree in tone; plausible reconciling factors are encoder type/size (Whisper-large-v2 weakly-supervised on 680k h vs WavLM), dual encoders, adapter capacity (76.6M trainable), and training-data scale — none of which were controlled in a single study. No paper found tests this on Qwen3-ASR / an AuT-style encoder.
- [inference] A projector with heavy temporal compression is a second potential loss point distinct from the encoder: Shi's code deliberately taps CTC before the conv downsampler (full frame rate) while the LLM gets the downsampled stream; a read-out placed *after* the projector would test the projector too.

### Gaps
- No direct layer-wise probing study of second-speaker lexical content in Whisper/WavLM/HuBERT/Qwen audio encoders was found; this appears to be a genuine literature gap (or was not discoverable through search snippets).
- Tencent Table 3 exact WERs (frozen-unadapted vs frozen-adapted vs unfrozen) and any MT-LLM ablation un-freezing the encoders were not retrievable.
- No encoder-frozen vs encoder-LoRA vs full-fine-tune three-way ablation for a multi-talker Speech-LLM was found.

## KQ5. Auxiliary training methods with zero inference cost (heads dropped at inference)

### Takeaway
They exist and are the cheapest option, but the measured gains are modest and inconsistent: SOT + auxiliary CTC (single-stream or per-talker via separator) helps mostly in noisy/3-talker conditions and showed **no gain on clean Libri2Mix** (SLT 2024), and the hybrid SOT-CTC stage **degraded** the LLM system in the ASRU 2025 paper; the larger gains come from variants that *use* the separated information at inference (GEncSep, SOP, cross-attention memory) or that replace the LLM altogether.

### Cited Findings
- **Per-talker CTC on separated encodings as an auxiliary loss (EncSep)**: >8% / >6% relative WER improvement on noisy Libri2Mix / Libri3Mix over SOT; **no improvement on clean Libri2Mix**. Using the separated encodings at inference (GEncSep) raises this to >12% / >9% relative. [search-extract] — [arXiv 2409.00815](https://arxiv.org/abs/2409.00815)
- **Same idea with an LLM decoder**: "during the second-stage training, the SOT-CTC model experienced performance degradation"; SOP (which consumes the CTC outputs at inference) improves significantly over both SOT and SOT-CTC. [search-extract] — [arXiv HTML 2509.04488](https://arxiv.org/html/2509.04488)
- **Code support for the zero-cost configuration**: `train_mode=hybrid`, `talker_ctc=true`, `ctc_bridge=false` → loss `0.7·CE + 0.3·mean CTC`; at attention-decoding inference the separator/CTC outputs are computed but not used by the LLM and can be dropped. [code-verified] — [losses.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/losses.py), [README training modes](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/README.md)
- **Single-stream speaker-aware CTC auxiliary (SACTC)**: SOT-SACTC consistently beats SOT-CTC across overlap ratios; the CTC branch is a training-time regulariser of the encoder. Magnitude **Not Reported — not retrievable.** [search-extract] — [arXiv 2409.12388](https://arxiv.org/abs/2409.12388)
- **Staged "adapt encoder with SOT/AED first, then freeze and attach LLM"** (a zero-inference-cost *training schedule*): best configuration in the Tencent study and reused by CMT-LLM. [search-extract] — [arXiv 2408.17431](https://arxiv.org/pdf/2408.17431), [CMT-LLM](https://www.isca-archive.org/interspeech_2025/he25_interspeech.pdf)
- **Reverse direction — LLM as training-time teacher, dropped at inference**: encoder-only serialized-CTC model distilled from an LLM-SOT objective; comparable to LLM systems at 2 talkers, better at 3, with small RTF. [search-extract] — [arXiv 2603.10587](https://arxiv.org/abs/2603.10587)
- **Mixture-aware pre-training** (WavLM utterance mixing; Cocktail HuBERT) is also zero inference cost but requires re-pretraining the encoder. — [arXiv 2110.13900](https://arxiv.org/html/2110.13900v5)

### Inferences
- [inference] For a 2-talker-only goal, the published evidence does not show a reliable WER gain from a drop-at-inference CTC head alone; its most defensible value for the team is **diagnostic** (per-talker CTC WER on the encoder = direct measurement of the research question) and as the first half of an SOP-style system, rather than as a guaranteed accuracy booster.
- [inference] Cost of the auxiliary head in training is not negligible if the CTC vocabulary is the LLM vocabulary (≈131M params per head in Shi's code); a smaller CTC vocabulary (characters / small BPE) would be cheaper but then cannot be embedded directly as an LLM prompt.

### Gaps
- No ablation was found that isolates "auxiliary per-talker CTC, dropped at inference" for a **two-talker Speech-LLM with a frozen or LoRA-tuned encoder**; absolute numbers for SOT vs SOT-CTC in the ASRU table were not retrievable.

## KQ6. How a separator / per-speaker CTC is attached to an encoder → projector → LLM pipeline (what is actually fed to the LLM)

### Takeaway
Published options, in increasing invasiveness: (A) feed the **original mixed features** and use separator+CTC only as a loss (EncSep / SOT-CTC); (B) **prepend CTC hypothesis text embeddings** to the original mixed features (SOP, ASRU 2025); (C) **replace/augment the prefix with time-concatenated separated streams** (GEncSep; `ctc_bridge=raw`); (D) keep the mixed prefix and give every LLM layer **gated cross-attention to the separated streams** (2603.27205); (E) Sidecar-style: split inside the encoder and run the rest of the model once per talker. No paper found **sums** separated streams; all "combine" variants concatenate along time or go through text.

### Cited Findings
- **(A) Loss only**: separator output → per-talker CTC; LLM prefix = downsampled + linearly-projected mixed encoder states. [code-verified] — [glue model](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/modeling_speech_encoder_decoder_llama.py)
- **(B) SOP**: `LLM input = [embed_tokens(greedy CTC ids of head 1 … head N)] ⊕ [projected mixed speech] ⊕ [decoder tokens]`; CTC vocabulary = LLM vocabulary; trained in a third stage with a fresh LoRA while the rest is frozen; LoRA merged afterwards. [code-verified + search-extract] — [ctc_prompt.py](https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs/blob/d955266085e130658007a747df58dff904a35c27/models/ctc_prompt.py), [arXiv HTML 2509.04488](https://arxiv.org/html/2509.04488)
- **(C) Concatenated separated streams**: `X = cat(sep_1, …, sep_N, dim=time)` → same conv downsampling adapter → `enc_to_dec_proj` → **replaces** the mixed prefix (prefix length × N). SLT paper: separated encodings "are concatenated to provide single-speaker information to guide attention during decoding". A learned softmax-weighted extractor variant carries the code comment "help for 2-talker, but no significant improment for 3-talker".
